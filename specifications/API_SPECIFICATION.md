# 酒まる印刷 API仕様書

## 概要
このドキュメントは、酒まる印刷クライアントアプリケーションが使用するAPIの仕様を定義します。

## エンドポイント

### 1. 印刷タスク取得API

**エンドポイント:** `POST /api/printer/tasks` (または設定で指定されたURL)

**リクエスト:**
```json
{
  "printer_pc_id": "192.168.1.100"
}
```

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| printer_pc_id | string | ○ | クライアントPCのローカルIPアドレス |

---

**レスポンス形式（推奨 - 指示5対応）:**

バッチ印刷に対応した新形式。複数の印刷ジョブを配列で返します。

```json
[
  {
    "file_url": "sample1.pdf",
    "printer_id": "1",
    "file_id": "12345",
    "order": 1
  },
  {
    "file_url": "sample2.pdf",
    "printer_id": "2",
    "file_id": "12346",
    "order": 2
  },
  {
    "file_url": "sample3.pdf",
    "printer_id": "1",
    "file_id": "12347",
    "order": 3
  }
]
```

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| file_url | string | ○ | S3バケット内のPDFファイルのキー（パス） |
| printer_id | string | ○ | 使用するプリンタ番号（"1"～"4"） |
| file_id | string | ○ | ファイルの一意識別子（ログ記録用） |
| order | number | ○ | 印刷順序（昇順で処理される） |

**動作:**
1. クライアントは配列内のファイルを最大4つ並列でダウンロード
2. ダウンロード完了順に関係なく、`order`フィールドの昇順で印刷を実行
3. すべての印刷が完了するまで次のポーリングは実行されない

**注意事項:**
- `printer_id`が"1"～"4"以外の場合、プリンタ1にフォールバック
- 指定された`printer_id`のプリンタが未設定の場合もプリンタ1にフォールバック
- ダウンロードに失敗したファイルはスキップされる

---

**レスポンス形式（旧形式 - 後方互換性）:**

**パターン1: プリンタ番号指定**
```json
{
  "file": "sample.pdf",
  "printer_number": "2"
}
```

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| file | string | ○ | S3バケット内のPDFファイルのキー |
| printer_number | string | ○ | 使用するプリンタ番号（"1"～"4"） |

**パターン2: プリンタ名配列指定（非推奨）**
```json
{
  "file": "sample.pdf",
  "printer": ["プリンタ名1", "プリンタ名2"]
}
```

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| file | string | ○ | S3バケット内のPDFファイルのキー |
| printer | array | ○ | プリンタ名の配列（順次印刷） |

---

**レスポンス: タスクなし**

印刷タスクがない場合は空配列または空オブジェクトを返します。

```json
[]
```

または

```json
{}
```

## S3設定

クライアント側で以下のS3設定が必要です：

| 設定項目 | 説明 | 例 |
|---------|------|-----|
| Bucket | S3バケット名 | `my-print-bucket` |
| Region | AWSリージョン | `ap-northeast-1` |
| AccessKeyId | AWSアクセスキーID | - |
| SecretAccessKey | AWSシークレットアクセスキー | - |

**ファイルパス:**
- APIレスポンスの`file_url`や`file`フィールドには、S3バケット内の**相対パス**を指定
- 例: `"documents/print_job_123.pdf"`

## クライアント動作フロー

### 新形式（バッチ印刷）の場合

```
1. クライアントがポーリングリクエストを送信
   POST /api/printer/tasks
   Body: {"printer_pc_id": "192.168.1.100"}

2. サーバーが印刷ジョブ配列を返却
   Response: [{file_url, printer_id, file_id, order}, ...]

3. クライアントがファイルをダウンロード
   - 最大4ファイル並列ダウンロード
   - すべてのファイルをS3から取得

4. クライアントがorder順に印刷実行
   - order=1 → order=2 → order=3 ...
   - 各印刷が完了後、次の印刷を開始

5. すべての印刷完了後、次のポーリングを実行
   - 設定された間隔（pollInterval）後に再度ポーリング
```

### 旧形式の場合

```
1. クライアントがポーリングリクエストを送信
   POST /api/printer/tasks
   Body: {"printer_pc_id": "192.168.1.100"}

2. サーバーが単一ジョブを返却
   Response: {file, printer_number} or {file, printer}

3. クライアントがファイルをダウンロード
   - S3から1ファイルダウンロード

4. クライアントが印刷実行
   - printer_numberの場合: 指定プリンタに印刷
   - printerの場合: 配列内の全プリンタに順次印刷

5. 印刷完了後、次のポーリングを実行
```

## ログ記録

クライアント側では以下のログが日別ファイルに記録されます：

- 印刷ジョブ受信
- ファイルダウンロード開始/完了/失敗
- 印刷開始/完了/失敗
- プリンタフォールバック
- APIエラー

**ログファイルパス:**
- macOS: `~/Library/Application Support/酒まる印刷/logs/log_YYYY-MM-DD.txt`
- Windows: `%APPDATA%/酒まる印刷/logs/log_YYYY-MM-DD.txt`

## エラーハンドリング

### クライアント側の動作

| エラー種別 | クライアント動作 |
|-----------|----------------|
| API接続失敗 | エラーログに記録、次のポーリング間隔で再試行 |
| HTTPステータス 4xx/5xx | エラーログに記録、次のポーリング間隔で再試行 |
| S3ダウンロード失敗 | 該当ジョブをスキップ、他のジョブは継続 |
| プリンタ未設定 | プリンタ1にフォールバック、ログに記録 |
| 印刷失敗 | エラーログに記録、次のジョブに進む |

### 推奨されるサーバー側エラーレスポンス

エラー時は適切なHTTPステータスコードを返してください：

```json
{
  "error": "エラーメッセージ",
  "code": "ERROR_CODE"
}
```

## 設定パラメータ

クライアント側で設定可能な項目：

| パラメータ | 説明 | デフォルト |
|-----------|------|----------|
| pollInterval | ポーリング間隔（ミリ秒） | 5000 |
| apiAddress | 印刷タスク取得APIのURL | - |
| printer1～4 | プリンタ1～4の名前 | （未設定） |
| s3.bucket | S3バケット名 | - |
| s3.region | AWSリージョン | - |
| s3.accessKeyId | AWSアクセスキーID | - |
| s3.secretAccessKey | AWSシークレットアクセスキー | - |
